============================================================
1. TASK GOAL
============================================================

Task 2 is the fixed-point robotic-arm pick-and-place experiment.

The required overall sequence is:

1) Home
2) Move above pickup point A
3) Descend
4) Grasp the object
5) Lift to a safe height
6) Move above placement point B
7) Descend
8) Release
9) Return home

The task is first implemented in simulation and later transferred to the real mechArm 270 while keeping the same ROS 2 task logic as much as possible.

The simulation must ultimately contain:

- mechArm 270
- gripper
- table
- fixed target object
- fixed pickup point A
- fixed placement point B
- safe travel height
- ROS 2 control interface
- exception handling
- one Launch file for the complete simulation
- execution result / trajectory / error logging

User workflow requirement:

- Push to the group GitHub repository.
- Jetson is mainly used to git pull, build and run ROS 2 / Gazebo.
- Do not perform unnecessary extra tests or repeated QC checks. Directly advance the task unless an actual error appears.

============================================================
7. IMPORTANT CURRENT MODEL FIX
============================================================

A previous Launch successfully reached the following stages:

- task2_sim package launched
- robot_state_publisher started
- robot links base through link6 were read
- ros_ign_bridge created the Gazebo -> ROS /clock bridge
- Gazebo world started

Then spawning the original official URDF failed with errors similar to:

link[base] has no <inertial> block defined

and later:

A model must have at least one link

Root cause:

The official mechArm_270_m5 URDF is suitable as a robot description / kinematic model, but Gazebo physics requires inertial properties on links.

A new Gazebo-ready model was therefore created on the Mac and committed:

tak2/ros2_ws/src/task2_sim/urdf/mecharm_270_gazebo.urdf

This model keeps the official Elephant Robotics mesh resources and joint structure / limits, while adding:

- inertial blocks
- approximate masses
- approximate inertia tensors
- simplified collision geometry
- joint damping
- joint friction
- non-zero velocity limits

The corresponding task2_sim/setup.py was updated so the urdf/*.urdf files are installed.

The Launch file was also updated to use:

mecharm_270_gazebo.urdf

instead of directly spawning the original official URDF.

IMPORTANT:
This latest Gazebo-ready model commit has been pushed from the Mac to GitHub, but as of the handoff moment the Jetson has NOT yet successfully pulled this newest commit.

============================================================
8. CURRENT LAUNCH ARCHITECTURE
============================================================

File:

tak2/ros2_ws/src/task2_sim/launch/task2_sim.launch.py

Current intended Launch flow:

1) Set IGN_GAZEBO_RESOURCE_PATH so Gazebo can resolve package://mycobot_description/... mesh references.
2) Start Ignition Gazebo server with task2_world.sdf.
3) Start ros_ign_bridge for /clock.
4) Start robot_state_publisher with mecharm_270_gazebo.urdf.
5) After a short delay, call Ignition Gazebo EntityFactory service to spawn mechArm 270 into task2_world.

The robot spawn method uses:

ign service

instead of ros_ign_gazebo / ros_gz_sim because the required binary route was not available on this Jetson ARM64 setup.
